Important Disclaimer

This is an educational demonstration. Our project runs on SQLite on a single laptop. No actual RAID hardware has been configured. The information below explains RAID concepts and justifies a theoretical design choice for a hospital database.

RAID 0 — Striping

Data is split (striped) evenly across two or more disks with no redundancy. Read/write performance is maximised because multiple disks work in parallel.

┌─────────┐ ┌─────────┐
│ Disk 0 │ │ Disk 1 │
│─────────│ │─────────│
│ Block 1 │ │ Block 2 │
│ Block 3 │ │ Block 4 │
│ Block 5 │ │ Block 6 │
└─────────┘ └─────────┘
Pros
  • Best read/write performance
  • Full disk capacity utilised
  • Simple implementation
Cons
  • Zero fault tolerance
  • One disk failure = total data loss
  • Not suitable for critical data

RAID 1 — Mirroring

Every block is written identically to two (or more) disks. If one disk fails, the mirror contains a complete copy of the data.

┌─────────┐ ┌─────────┐
│ Disk 0 │ │ Disk 1 │
│ (main) │ │(mirror) │
│─────────│ │─────────│
│ Block 1 │ │ Block 1 │
│ Block 2 │ │ Block 2 │
│ Block 3 │ │ Block 3 │
└─────────┘ └─────────┘
Pros
  • Full redundancy — survives single disk failure
  • Fast read speed (can read from either disk)
  • Simple recovery
Cons
  • 50% storage overhead
  • Write speed same as single disk
  • Expensive per usable GB

RAID 5 — Distributed Parity

Data and parity information are striped across three or more disks. Parity allows reconstruction of data if any single disk fails.

┌─────────┐ ┌─────────┐ ┌─────────┐
│ Disk 0 │ │ Disk 1 │ │ Disk 2 │
│─────────│ │─────────│ │─────────│
│ Block 1 │ │ Block 2 │ │Parity12 │
│Parity34 │ │ Block 3 │ │ Block 4 │
│ Block 5 │ │Parity56 │ │ Block 6 │
└─────────┘ └─────────┘ └─────────┘
Pros
  • Good balance of performance and redundancy
  • Only one disk's worth of capacity lost to parity
  • Survives single disk failure
Cons
  • Write penalty (parity must be calculated)
  • Rebuild time can be long
  • Vulnerable during rebuild if a second disk fails

RAID 10 — Striping + Mirroring Selected Design

Combines RAID 1 mirroring with RAID 0 striping. Data is first mirrored (for safety), then the mirror pairs are striped (for speed). Requires a minimum of four disks.

┌───── Stripe 0 ─────┐ ┌───── Stripe 1 ─────┐
│ Disk 0 │ Disk 1 │ │ Disk 2 │ Disk 3 │
│(mirror) │ (mirror) │ │(mirror) │ (mirror) │
│─────────│──────────│ │─────────│──────────│
│ Block 1 │ Block 1 │ │ Block 2 │ Block 2 │
│ Block 3 │ Block 3 │ │ Block 4 │ Block 4 │
└─────────┘──────────┘ └─────────┘──────────┘
Pros
  • Excellent read/write performance
  • Full redundancy within each mirror pair
  • Fast rebuild — only the failed disk's mirror is copied
  • Ideal for I/O‑intensive, mission‑critical workloads
Cons
  • 50% storage overhead (same as RAID 1)
  • Requires minimum 4 disks
  • Higher hardware cost

Why RAID 10 for a Hospital Database?

Patient Safety

Medical records must never be lost. Mirroring guarantees an identical copy exists at all times.

High Performance

Striping spreads I/O across disks, keeping response times low during peak hours.

Fast Recovery

Rebuild involves copying only one disk from its mirror — minutes instead of hours.

24 / 7 Availability

Hospitals operate around the clock. RAID 10 lets the system keep running even during a disk failure.

RAID Is Not a Backup

RAID protects against hardware failure but not against accidental deletion, ransomware, or software corruption. A comprehensive disaster‑recovery strategy still requires regular off‑site backups, point‑in‑time recovery, and tested restore procedures.
