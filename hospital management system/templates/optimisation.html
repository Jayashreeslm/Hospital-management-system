Before vs After — Column Selection

Before (Inefficient) 

SELECT *
FROM Appointment
WHERE Patient_ID = 101;

SELECT * retrieves every column from the table, including ones the application doesn't need. This wastes I/O bandwidth, memory, and network transfer — especially problematic when tables have many columns or large TEXT/BLOB fields.

After (Optimised) 

SELECT Appointment_ID, Doctor_ID, DateTime
FROM Appointment
WHERE Patient_ID = 101;

Listing only the required columns reduces the amount of data the engine must read and transfer. In combination with a covering index, the engine may satisfy the query entirely from the index without touching the table at all.

Index Optimisation

An index on the Patient_ID column of the Appointment table allows the database engine to jump directly to matching rows instead of scanning every row (full table scan → index seek). 

CREATE INDEX idx_appt_patient ON Appointment(Patient_ID);

With this index in place, queries filtering on Patient_ID execute in O(log n) time instead of O(n). For a table with thousands of appointments, the difference is dramatic.
